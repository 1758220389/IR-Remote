# STM32 独立手势识别 V1.0.0

## 启动

用配套固件和同一次构建生成的 Keil map。关闭其他 SWD 采集或调试程序后，双击 [Start-Recognition.cmd](../Start-Recognition.cmd)。软件在 BT6 松开且原采集缓存已确认时请求切换，窗口分别显示 MCU 输出和 Python 对照。SWD 读取最新完整结果，不向识别缓存写确认。快速连续动作时，PC 可能跳过已被下一条覆盖的结果，可用窗口编号看出。

脱离 PC 时，按住 BT6 后给板上电或硬复位，启动后松开。等传感器初始化，再按下并旋腕、松开。普通上电默认保留采集模式。双击 Start-Capture.cmd 会在空闲时切回采集模式，继续使用冻结缓存及保存确认。

## 模型和算法

方案 C 的 joblib 与 JSON 一致，标准化器记录 120 个拟合样本，四个训练会话的主集为 CW、CCW、NONE 各 40 个。10 个补充 CW 仅用于附加测试。export_recognizer.py 校验训练清单哈希、类别顺序、折叠系数和静置零偏，再生成模型头文件。协议模型版本为 0x00010000，输出顺序固定为 CCW、CW、NONE；拒绝是独立状态。三轴训练零偏为 +6.525539、+1.259047、−1.161972 °/s，C 只使用 Z 零偏。

以 131 LSB/(°/s) 转换。每对相邻样本先检查板载时差为 10 ms，再对 Z 做梯形积分。C 累加相邻原始值之和，在窗末乘 0.005/131，再减去零偏乘首末采样跨度。这与逐点单位换算后积分代数等价。计算三个仿射分数，比较最大值。用训练时固定的零偏。按键时长仅用于质量判断。

短于 150 ms、截断、点数与时长不符、异常采样间隔及任一轴饱和的窗口拒绝。I²C 失败则取消采集。达到 1.5 s 后保持等待松开。识别结果只写本地 RAM，采集缓冲区与正式遥控器均不派发红外命令。

## 验证

- ARMCC 5.06u5 全量编译，0 错误、0 警告。链接 Flash 13,952 B、RAM 8,328 B。相对已验收 v4 的 11,664 B / 8,264 B，增加 2,288 B / 64 B。应用映像在前 48 KiB 内。
- Windows 编译同一份 C 后重放冻结清单的 130 窗。128 个未截断窗与 Python 一致，两个截断窗按部署规则拒绝。最大角度差 0.00000389°，最大分数差 0.00000024。最近边界的是实际 CW、两端均判 NONE，Z 积分 −14.789956°，前两分数差约 0.002904。另验证短窗、点数不符、采样间隔异常和饱和拒绝。
- 烧录前应读回备份 64 KiB。按扇区下载应用映像，逐字节读回应用与末尾 16 KiB 配置区。接通实板后可用 replay_recognizer.py --pack <设备包路径> 重放 ARMCC 输出，结果写入 ml/models/v1/mcu_parity.csv。回放会短暂停核并复位独立板，只改测试用 RAM。
- DWT 周期只计六轴质量检查、Z 积分和评分，排除 I²C、复制、SWD 和界面开销。板端采集窗口周期间隔及实际核心频率需一并核对。已通过 ST-Link 仅按扇区烧录，完整 64 KiB 备份位于 ml/data/flash-backups/20261117-230727-recognition，固件映像和末尾 16 KiB 均读回验证。板上 ARMCC C 回放也通过 128 条未截断窗口，两条截断拒绝，最大角度差和分数差与 Windows 回放相同。实体动作和 DWT 耗时另见后续验收记录。

验收顺序：先在识别窗口做 CW、CCW、静置、快速轻点、超过 1.5 s 长按。确认拒绝状态与分类编号。关闭识别窗口、保留供电并做两次动作。重新打开识别窗口时，确认 MCU 编号前进两次且最后一条与 PC 对照一致。最后切回采集界面检查旧保存确认流程。

### 实板实时验收

- 实体 BT6 得到编号 #1–#4。三个正常窗口分别为 CCW、NONE、NONE，均与同一窗口的 Python 对照一致。1500 ms / 150 点的第四窗截断并拒绝，两端拒绝原因一致。
- 板载核心时钟实读 72 MHz。实体正常窗口 44–94 点，DWT 实测 9,017–17,968 周期，即 125.24–249.56 µs。误触与截断提前退出约 3.4–3.5 µs。测试区间含全部六轴样本质量检查、Z 积分和评分。
- 实板 PB15 开漏模拟复测了连续有效触发和 77 ms 误触。长按开始后完整关闭 SWD 会话，保持板供电，重连后确认离线期间仅发布了一条截断拒绝，随后正常窗口继续发布，始终没有采集缓存等待确认。测试结束恢复原 GPIO 配置。
- 第一次尝试在关闭 GUI 后做实体独立运行验证时，板端已回到普通上电模式且编号清零，结果无法作为连续运行的证据。受控短断开结果见上，长时间实体连续验证以复测结果为准。
- 第二次实体离线复测后，重连实读模式值为采集、识别编号为 0，未读到两次 CW 的结果。操作者确认动作时接线松散，曾发生供电中断。断电清除 RAM 并按普通上电进入采集模式；PC 端已保存的数据仍可用于继续原会话。受控保持供电的 SWD 断开验证已通过，实体离线两次 CW 仍待固定接线后复测。

当前正式遥控器已完成控制集成与实体升降温验收，见 [整合报告](SHADOW.md)。本文资源增量和运行方式仅属于独立识别固件。
