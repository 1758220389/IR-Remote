# 基于单片机的家电智能遥控器系统设计

## 项目目标/功能
基于STM32F103C8T6芯片开发，语言不限，开发一个红外遥控器，要求
1. 使用红外模块发送信号，控制电器
2. 红外学习功能，根据已有遥控器发送的信号学习，并绑定至已有的按键
3. 多设备控制，可保存多个配置文件进行控制，断电后仍保存配置文件
4. 配置显示功能，使用数码管或oled显示屏进行配置的选择
5. 改电池供电
6. 可连接至电脑进行配置管理

## 硬件连接

## OLED 操作页面（当前实现）

使用 Keil 打开 `code/IR_Remote.uvprojx`。工程已接入主循环和 1ms SysTick，采用标准外设库；OLED 使用已有驱动，SCL=PB9、SDA=PB8（软件 IIC）。ARMCC5 的 `--no_multibyte_chars` 保证 UTF-8 中文字符串按原始字节编译，勿随意移除。

### 按键

每组按键前一个引脚输出低电平，后一个引脚为上拉输入，按下短接。软件对按下和释放均作 20ms 防抖；长按阈值为稳定按下后 1000ms，每次按压仅触发一次长按，松手不再触发短按。上电时已按住的键须先释放才能操作。正常页短按 BUTTON1～5 均产生红外发送接口事件；长按 BUTTON5 进入设置，BUTTON1～4 长按当前不发送。

| 页面 | 操作 |
| --- | --- |
| 正常使用 | 显示当前配置，长按 BUTTON5 进入设置 |
| 设置 | BUTTON1 向上、BUTTON2 向下循环选择“学习、配置1、配置2、配置3”；BUTTON5 短按确认，显示什么就进入什么；长按 BUTTON5 返回 |
| 学习：接收中 | 等待真实红外输入；未绑定信号时长按 BUTTON5 退出，已绑定后长按 BUTTON5 进入保存位置选择 |
| 学习：已接收 | 短按 BUTTON1～5 任一键绑定，再回到接收中；重复绑定同键覆盖本轮信号 |
| 保存至 | 短按 BUTTON1／2 循环选择配置；长按 BUTTON5 整份替换目标配置；长按 BUTTON1～4 任一键取消 |
| 结果 | 显示保存／取消／失败结果，1 秒后返回原先活动配置的正常页 |

设置页标题与保存页目标配置每 500ms 闪烁。中文采用 16×16 点阵，每行最多 8 个汉字，长提示按实际屏幕大小分行。正常页与学习页标题不闪烁。

### 当前范围与后续接口

- 已接入 PB7 红外原始时序学习、PB6 载波调制重放和片内 Flash 持久化；电池管理、电脑配置管理仍未实现。不会自动注入虚假接收信号。
- 启动时从 Flash 恢复 3 份配置和最后活动配置；无有效记录时初始化为空。保存后显示 `已保存 / FLASH`。切换配置稳定 1 秒后写入最后选择，期间断电可能恢复到上一次选择。
- `app.h` 的 `App_ReceiveSignal()` 接收未来驱动采集到的信号，须在主循环上下文调用；中断内只入队，不能直接刷新页面。
- `App_SetBackend()` 注册发送和保存回调。发送回调的空信号指针表示该键未绑定；保存回调只有确实完成持久化才返回非零，失败返回零并保留原配置。默认注册真实红外发送和 Flash 保存后端。
- `UiSignal.format` 明确区分 RAW 与紧凑 BOSCH144。RAW 最多 255 个微秒时长，首尾为 mark；BOSCH144 以 18 字节开机状态／12 字节关机指令保存，并流式生成 299／199 段包络，不需要增大所有按键的原始数组。1838B 只能接收解调包络，学习载波默认 38kHz，不代表实测频率。配置编号在 API 内为 0～2，按键编号为 1～5。
- `App_GetState()` 可供 Keil 观察页面与配置，不应通过强制转换修改返回对象。

### 红外与 Flash 实现范围

- 红外接收：PB7 / TIM4 TI2 双沿硬件捕获，DMA1 通道 1／4 分别保存下降／上升沿，替代会漏边沿的 EXTI 软件路径；TIM2 提供间隔／超时参考。30ms 静默判定完成，最长 1 秒；DMA 溢出、截断 BOSCH144、校验错误均拒绝。页面显示 `RX INVALID` 时短按 BUTTON5 重试，长按保留退出／保存含义。未知超长原始协议仍不支持。
- 红外发送：PB6 / TIM4_CH1，约 1/3 占空比；TIM3 中断推进包络。发送不阻塞主循环，发送期间屏蔽自收，结束后留出 30ms 稳定间隔。未绑定、发送忙或信号非法时不会发射。
- 应用链接空间限制为前 48KB；`0x0800C000` 和 `0x0800E000` 各保留 8KB 存储银行。记录包含格式版本、递增代数、CRC32 和最后写入的提交标记；保存时只擦除旧银行之外的目标银行，失败保留前一有效记录。
- 下载应使用 **sector erase**，不要全片擦除，否则配置会丢失。首次升级前的 UI 固件仅 RAM 保存，原 RAM 数据无法迁移。
- 型号 `rn10l2b2hs/bgh` 的真实 DMA 采集前两节及第三节前缀与 BOSCH144 结构和用户报告的制冷／自动风／25.5℃一致，但尾校验字节缺失。**配置一提供待实机确认的候选预置**：以实收前缀加公开协议重新计算的校验码 `0x5B` 生成，不能描述为完整采集或已经控制成功。只在配置一为空时初始化，不覆盖已有学习配置。
- 已通过 ST-Link 下载通用学习固件并逐字节回读核对；实板 72MHz 时钟、SysTick 运行和无故障状态已检查。通过调试器仅改变活动配置，由固件完成 Flash 写入，MCU 复位后恢复成功，随后恢复原配置选择；这不等同于拔电测试。红外真实收发效果及原遥控器协议仍待现场采集验证。
- RAW 学习上限为 255 段、相邻边沿间隔须小于 65536µs，载波按 38kHz 假定；BOSCH144 形状的报头保留给严格解码，其他共享报头的协议可能被拒绝而不会降级保存为 RAW。
- 候选控制版已下载并逐字节回读核对，确认下载未擦除保留区后才首次启动。启动后配置一候选成功写入 schema 2，MCU 复位后恢复成功；无 CPU 故障，且没有自动发射。**空调实际响应和 TX 包络仍待用户现场验证。**
- `tools/check_link_layout.py` 核对生成的链接命令和 map 边界；`tools/test_link_overflow.py --output-dir <scratch>` 实际调用 ARM 链接器确认越界镜像被拒绝。不能只检查 Keil GUI 的 IROM 大小。
- 诊断可观察 `g_app_diagnostics`（接收帧数、最近长度、发送次数和保存结果）及 `App_GetState()`；不要把主机模拟测试当作实板电气验证。

### 配置一：空调动态控制（用户初测部分有效）

用户已实测：温度调节、风速调节和开关能使空调响应；模式键也有响应，但实际模式是否切换尚未确认。随后报告 BT4／BT5 无响应，其余功能正常。故障时读取到按键 raw/stable/blocked/long 掩码均为零，发射定时器空闲、CPU 无故障；仅凭该快照不能确定原因，不能宣称已修复。

按用户要求重刷时，连接／复位阶段出现 ST-Link DP/IDCODE 错误，100kHz 和复位连接重试仍无法探测目标；本次尚未执行新的擦除／编程，待检查供电／SWD 连接后继续。此前完整下载、回读及复位保存测试已通过。


- BUTTON1／2：±0.5℃，范围 16～30℃；BUTTON3：自动→制冷→除湿→制热→送风循环。
- BUTTON4：自动→20%→40%→60%→80%→100% 风速循环。进入自动／除湿时按上游协议设置专用自动风编码；具体空调可能限制这些模式的风速。
- BUTTON5 短按：开／关；长按：进入设置，不额外发射短按指令。
- OLED 显示本机期望状态，不是空调回传状态。发送忙时不更改本机模型。关闭电源仍保留最近温度／模式／风速；再开机发送完整状态。
- 选择或模型变化稳定 1 秒且发射空闲后保存至 Flash；不是每次按下立即擦写。保存完成前断电可能回到上次记录。
- 直接学习并整份保存到配置一会将其替换为普通学习配置；不会偷偷重新覆盖为候选预置。
- Flash 使用 schema 2，显式保存信号格式与配置种类；schema 1 不会被误读或自动迁移。本次此前只有空配置，升级前仍备份整个保留区；有旧格式学习数据时须先导出并另行迁移。
- `bosch144.*` 改编自 IRremoteESP8266，许可与来源见 `third_party/`。完整源码、工程和构建文件随仓库保留；发布固件需遵守相关 LGPL 义务。
